# 開發規劃 (Roadmap)

目前優先開發 **planner** 與 **client**；map 與 server 暫停，待單人的進度規劃可以使用後再恢復。
整體設計見 [`architecture.md`](architecture.md)。

## 階段 (Phases)

| 階段 | 內容 | 狀態 |
|---|---|---|
| 0. 說明與設計 | README、LICENSE、架構設計文件、開發規劃、上傳規則（`.gitignore`）與檔案格式檢查 | 完成 |
| 1. 骨架 | planner（WPF）與 client（.NET 10）空白專案、solution、CI | 未開始 |
| 2. 驗證實驗 | 讀取遊戲紀錄檔（log）與截圖資料夾，確認能取得哪些任務事件與座標格式 | 未開始 |
| 3. protocol | 定義 client ⇄ planner 的事件與資料格式 | 未開始 |
| 4. client | 讀取 log、本機中樞、系統匣常駐 | 未開始 |
| 5. planner MVP | 任務進度（log 自動＋手動修正）、出發前清單、鑰匙、藏身處 | 未開始 |
| — map | 位置、任務點、路線與標記 | 暫停 |
| — server | 小隊共享、主題公開與訂閱 | 暫停 |

## 待驗證事項 (Open Questions)

| 項目 | 說明 | 驗證時機 |
|---|---|---|
| log 內容 | log 是否記錄任務開始、完成、失敗；能否取得目標細項進度 | 階段 2 |
| 藏身處、鑰匙 | log 是否有相關資訊，或只能手動輸入 | 階段 2 |
| 截圖檔名格式 | 座標格式是否與先前的版本相同 | 階段 2 |
| 資料授權 | tarkov.dev 資料與地圖圖檔是否允許本專案使用 | 使用前 |
| OCR 準確度 | Windows 內建 OCR 對英文、繁中、簡中的辨識效果 | 導入圖像辨識時 |
