# 0005. 進度來源：log 自動＋手動修正

- 狀態：已採用（待驗證）
- 日期：2026-10-24

## 背景

planner 需要知道使用者的任務進度、鑰匙與藏身處狀態。不讀取遊戲記憶體的前提下，可用的來源是遊戲寫在本機的紀錄檔（log）與使用者手動輸入。

## 決策

- client 監聽遊戲 log，自動更新偵測得到的狀態
- planner 提供手動修正與設定，處理 log 讀不到的部分
- 鑰匙與藏身處很可能以手動輸入為主，planner 的手動操作必須好用

## 理由

- 社群中已有讀取 log 偵測任務狀態的工具，方向可行，但實際內容尚未驗證
- log 只能偵測工具開啟後發生的事件，舊進度需要手動設定或匯入

## 待驗證

由「驗證實驗」階段確認（見 [`roadmap.md`](../roadmap.md)）：

- log 是否記錄任務開始、完成、失敗；能否取得目標細項進度
- 藏身處、鑰匙是否有相關資訊

驗證結果若推翻前提，新增一筆決策紀錄取代本紀錄。

## 影響

- planner 的資料模型要能區分「自動偵測」與「手動設定」的值
