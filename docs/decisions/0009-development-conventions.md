# 0009. 開發規範：分支、commit 與程式風格

- 狀態：已採用
- 日期：2026-10-24

## 背景

開發主要由 Claude（agent team）依 issue 進行，需要明確、可檢查的規範，讓成果一致，也讓使用者容易審核。

## 決策

- **分支**：`<類型>/<issue 編號>-<簡短英文說明>`，例如 `chore/1-skeleton`
- **commit**：`<類型>(<範圍>): <繁體中文摘要> (#<issue 編號>)`，例如 `chore(repo): 建立 planner 空白專案 (#1)`
- 類型與範圍的完整定義見 [`workflow.md`](../workflow.md)
- **程式風格**：見 [`coding-style/`](../coding-style)，**依語言分檔**（通用規則、C#、TypeScript），開發時只讀涉及的語言；可自動檢查的部分寫在 `.editorconfig`
- 每個 app 與套件的資料夾放一份 `CLAUDE.md`，只指向該處語言的風格文件與驗證指令
- **測試框架**：xUnit；與遊戲有關的邏輯一律以去除個人資訊的範例資料測試

## 理由

- 分支與 commit 帶有類型與 issue 編號，從名稱就能知道對應的工作與性質
- 類型沿用常見的 Conventional Commits 慣例，摘要使用繁體中文以符合專案語言
- 開發者無法執行遊戲，必須依賴範例資料才能驗證

## 影響

- 不符合格式的分支或 commit 在審核時退回
- 骨架階段需建立 xUnit 測試專案，並在建置時啟用程式風格檢查
