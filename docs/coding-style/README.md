# 開發風格 (Coding Style)

開發風格依語言分成多個檔案。**只讀本檔案與你正在開發的語言對應的檔案**，不需要閱讀其他語言的規則。決策依據見 [`decisions/0009`](../decisions/0009-development-conventions.md)。

## 要讀哪一份

| 修改的路徑 | 語言 | 讀這份 |
|---|---|---|
| `apps/planner/`、`apps/client/`、`tests/` | C# · .NET · WPF | 本檔案 ＋ [`csharp.md`](csharp.md) |
| `apps/map/`、`apps/server/` | TypeScript · Node · Vue（暫停中） | 本檔案 ＋ [`typescript.md`](typescript.md) |
| `packages/protocol/schema/` | JSON Schema | 本檔案 ＋ 產生型別的目標語言那一份 |
| `docs/`、README 等文件 | Markdown | 本檔案 |

同一個 issue 同時修改多種語言時，才需要讀多份。

## 1. 通用規則（所有語言）

| 項目 | 規則 |
|---|---|
| 語言 | 程式註解、log 訊息、UI 文字、commit 訊息、文件：**繁體中文** |
| 識別名稱 | 類別、函式、變數等一律使用**英文** |
| 編碼、換行、縮排 | 依 [`.editorconfig`](../../.editorconfig)，由格式檢查自動確認 |
| 註解 | 說明「為什麼」，不重複「做了什麼」 |
| 魔術數字 | 抽成具名常數，並註解來源（例如遊戲 log 格式的欄位位置） |
| 未使用的程式碼 | 直接刪除，不保留註解掉的程式碼 |

## 2. 錯誤處理與日誌（所有語言）

- 只在能處理的地方捕捉錯誤，不吞掉錯誤
- 解析遊戲資料遇到無法辨識的內容：**記錄警告並略過**，不讓整個程式停止
- 給使用者看的錯誤訊息使用繁體中文，並說明下一步該怎麼做
- 日誌**不記錄**帳號、玩家名稱、token 等個人或機密資訊

## 3. 測試（所有語言）

- 與遊戲有關的邏輯一律用範例資料測試；範例資料放在 `tests/fixtures/`，必須先去除帳號、玩家名稱等個人資訊
- 修正錯誤時，先寫一個能重現錯誤的測試
- 各語言的測試框架與命名方式見對應的語言檔案

## 4. 相依套件（所有語言）

新增套件前確認：

1. 授權允許用於非商業專案（MIT、Apache-2.0、BSD 等）
2. 仍在維護
3. 沒有現成的內建功能可以取代

新增的理由寫在回報或 PR 中。

## 5. 文件

- 行為、設定或結構改變時，同步更新相關的 README 與 `docs/`
- 新的設計決策寫成 [決策紀錄](../decisions)
- 標題採「中文 (English)」格式，例如「如何開始 (How to start)」
